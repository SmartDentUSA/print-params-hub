- wa-dispatcher marks a campaign finished only when its last node was sent and no queue row of that campaign is still pending/sending; the claim RPC only picks active campaigns, so finishing on the first group stranded every other group of a blast.
- Flow campaigns (`campaign_type='flow'`) are ordered in the database: `claim_pending_wa_messages` serializes claims with an advisory lock and only releases a queue row when its campaign+group has nothing `sending` and no `pending` row with lower sequence_no (future ones included); wa-dispatcher marks rows stuck in `sending` >10 min (by `claimed_at`) as sent when wa_send_log has a success, else failed without resend, so overlapping cron runs never reorder or duplicate flow messages; wa-delivery-reconciler never requeues flow rows (it only marks `failed_undelivered`), resend stays a manual action.
